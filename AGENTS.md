# 3DPrintTally — architecture map and working rules

Read this before changing anything. It exists so you do not have to rediscover
the codebase, and so the decisions below do not get "fixed" by someone who
assumes they were accidents.

It is addressed to contributors and to AI coding assistants alike.

## What this is

A Flask app for product SKUs, bill-of-materials, label sheet printing and job
costing in a small 3D printing shop. It is a tool people price real customer work
with, which sets the bar for changes: a wrong number here costs someone money.

- Stack: Flask + gunicorn + ReportLab, SQLite at `data/labels.db` (bind mount)
- One container for the app, one sidecar for scheduled backups, one one-shot
  service that fixes volume ownership so the app can run non-root
- No external services. No telemetry. No network calls at runtime.

## Non-negotiable rules

- **Never commit, print or copy the contents of `.env`.**
- **Never run `reset-catalog.py` against a live install.** It clears products,
  parts, job costs and photos.
- **Never remove or disable manual entry anywhere.** Fields are free text with
  autocomplete, not constrained dropdowns. A shop that cannot type a value by
  hand is a shop that has to wait for a developer. Any proposal that locks a user
  out of typing a value will be rejected.
- **Saved job costs are frozen.** No recompute path, ever. See
  [docs/COSTING-MODEL.md](docs/COSTING-MODEL.md) section 9.
- **Verify by running it, not by asserting it.** Show real output.
- **Never state a fact about this codebase you have not read.**

## Out of scope by decision, not by omission

Opening an issue for these is fine; a PR adding them will likely be declined
without prior discussion.

- Multi-user accounts, roles or permissions. Authentication is a single optional
  HTTP Basic credential, on the assumption that a reverse proxy or VPN does the
  real access control.
- Finished-goods / countable unit inventory. Filament grams are tracked;
  finished units deliberately are not.
- Draft / revision / audit-trail machinery on job costs.
- Nested assemblies beyond one level.
- Printer or slicer integration. Print time is typed in from the slicer.
- Order pipeline, customer records, or a customer-facing portal.

## Layout

- `app.py` — routes and catalog/job orchestration
- `config.py` / `database.py` / `schema.py` — configuration, connections, serialized migrations
- `costing.py` / `pdf_output.py` — pricing calculations and PDF generation
- `catalog_csv.py` — version 2 CSV with validation and preview/confirmation
- `product_collections.py` — collection names and catalog filtering, over `products.category`
- `quickbooks_export.py` — read-only product identity CSV for QuickBooks Online
- `filament.py` — filament pools, transactions, cost per gram
- `security.py` / `validation.py` / `photos.py` — request protections and safe uploads
- `backup_tools.py` — consistent snapshots, full backups, restore verification
- `tests/` — disposable-data regression suite
- `templates/` — Jinja templates. Note: `/guide` renders `GUIDE_TEMPLATE`, a
  string literal in `app.py`, not a template file — so deploying `app.py` alone
  cannot leave a dead link behind.
- `data/` — live SQLite plus product photos. Excluded from git. Not covered by
  the repo; the Compose backup service snapshots it, off-host copying is yours.

## Data model

- `products` — `sku` is the PRIMARY KEY and the identity. `department` is a
  nullable column on the sellable product, blank for shared components.
  `category` is displayed as Collection. One collection per product; names are
  free text with reusable suggestions. Do not renumber SKUs when collections change.
- `product_parts` — the pieces that make up ONE product. A one-piece product has
  one row. FK on `sku` with `ON DELETE RESTRICT`.
- `assembly_components` — links an assembly product to other products as
  components, with quantities. **One level of nesting only.** A component may not
  itself be an assembly; self-reference and both nesting directions are rejected
  in application logic, because foreign keys cannot prevent a cycle.
- `job_costs` — `payload_json` holds the complete inputs, the parts snapshot and
  the computed result. Read directly, never recomputed.
- `filament_types` / `filament_transactions` — keyed by brand + material + colour.
  In a live install this is the table set most likely to hold substantial real
  data. Treat any change to it as a migration, not a schema edit.
- Also: `print_jobs` (label sheets, unrelated to costing), `settings`,
  `design_sessions`.

`PRAGMA foreign_keys=ON` on every connection, in both `app.db()` and `filament.db()`.

## SKU convention

Format is `TYPE-NNN` — e.g. `SGN-003`, `BASE-001`. Generated by `api_next_sku()`,
validated by `SKU_RE`.

Department is **not** in the SKU. It lives in its own column on the sellable
product and is blank for shared components, because a base or stem used across
departments is one physical object and must have exactly one SKU.

The item type segment is **free text** with an autocomplete list. Anything typed
by hand must work. Do not constrain it.

A SKU is deliberately colour-agnostic. `SGN-001` is the same part in white or
blue. Linking a filament pool to a part is a cost estimate only, never a binding
colour choice — the Job Calculator picks colour per job.

## Costing

The full model, including the parts that look like bugs and are not, is in
[docs/COSTING-MODEL.md](docs/COSTING-MODEL.md). Read it before touching
`costing.py`. The short list of traps:

- Per-unit cost is `part_total_cost / units_produced`, never `cost_per_part`.
- Scrap is a run-count increase on multi-plate jobs and a cost uplift on
  single-plate jobs. The two mechanisms are not interchangeable.
- `design_rate` is not `labor_rate`, and design time is never per-item.
- `calculate_pricing()` truncates, `calculate_quick()` does not. Both are
  intentional. Do not unify them.

## Security posture

Documented in [SECURITY.md](SECURITY.md). In code: CSRF on every mutating
request with constant-time comparison, an Origin check, a per-request CSP nonce,
`read_only` containers with `cap_drop: ALL`, non-root UID, a file lock
serializing writes, request size caps, and uploaded images re-encoded to strip
trailing payloads.

Authentication is **off by default** and the app binds to loopback. Any change
that widens the default exposure needs a very good argument.

## Testing

```sh
pip install -r requirements-test.txt
python -m unittest discover -s tests -v
python tools/check_dependencies.py
```

Tests use disposable data directories and never touch a live database. The
dependency check sends only package names and versions to OSV. Keep manual entry,
catalog identity, one-level assemblies and frozen saved-job calculations intact
when extending the app.

## Deploy gotcha worth knowing

Reset the umask to 022 before extracting a release archive. A shell left at
`umask 077` — for example after taking a private backup tarball — extracts source
at mode 600. Docker copies those modes into the image and the non-root container
dies with `PermissionError: /app/app.py`. After any extract, confirm
`ls -la app.py` shows 644 before building.
